## About me

I spend most of my time in TypeScript, thinking about how software fits together: where boundaries belong, what an API promises, and how to keep a codebase understandable as it grows.

I'm particularly interested in the relationship between type safety and runtime behaviour. I like explicit contracts, useful abstractions, and patterns that make it easier to reason about what the code actually does.

Developer experience matters to me. That includes the everyday things: finding the right place for a change, understanding a failure, running checks, and getting a local environment working without a scavenger hunt.

I enjoy working with engineers who challenge my thinking. Comparing approaches, questioning assumptions, and learning from the people around me are a big part of how I improve.

## What I care about

- **Clarity** — code and architectural decisions that other people can follow.
- **Correctness** — types, runtime validation, and tests that complement each other.
- **Simplicity** — abstractions that earn their place and complexity kept in check.
- **Maintainability** — considering how today's decisions affect the next change.
- **Shared understanding** — documenting the reasoning behind a decision, not just the result.
